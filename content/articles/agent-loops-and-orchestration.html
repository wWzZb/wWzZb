五种模式的执行过程

先看最基础的单 Agent 工具调用循环，再看四种常见的编排方式。它们不全是同一层级：工具循环描述一个 Agent 怎么工作；编排描述任务与控制权如何组织。Graph / Workflow 也可以只包含一个 Agent 或普通代码节点。

单 Agent：经典的工具调用循环（ReAct 思路）

一个 Agent 接收目标，调用模型决定下一步；需要工具就由程序执行，把结果放回上下文，再调用模型，直到给出答案或触发停止条件。原始 ReAct 交替组织推理、行动与观察；现代工具调用循环不一定使用显式的 Thought / Action / Observation 文本格式。

用户目标 + 消息上下文
→
调用模型，决定下一步
↓
需要调用工具？
→ 否
最终回答
↓ 是
程序执行搜索 / 读文件 / 测试
→
工具结果写入上下文
↺ 带着新结果，再次调用模型

架构方案

控制权
一个 Agent 决定工具与参数；Harness（运行环境）实际执行工具，并管理权限、预算和停止条件。
上下文
目标、历史消息、工具调用及返回结果构成上下文；运行环境可裁剪或压缩历史。
循环条件
模型提出工具调用 → 执行工具 → 记录结果 → 再调用模型。模型也可以直接回答。
结束条件
给出最终回答，或达到配置的预算 / 轮数 / 超时；用户取消、不可恢复错误也会停止。

适用与代价

适合
搜索问答、文件处理、代码修改、数据分析；一个 Agent 配合工具就能完成的任务。
主要优点
结构简单、容易追踪；可按工具结果调整下一步，不必提前写死全部步骤。
主要风险
可能反复调用工具、误判任务完成或积累过长上下文；需要执行权限、预算和结果校验。
